DATABASE MODELS (DETAILED)
================================================================================

UserProfile
  • user (OneToOne → Django User)
  • role (Admin, Technician, Normal User)
  • is_active (Boolean)
  • is_suspended (Boolean)
  • max_active_tickets (Integer, default 8)
  • created_at, updated_at (Timestamps)

TechnicianGroup
  • name (String, unique)
  • description (Text)
  • max_tickets_per_tech (Integer)
  • technicians (ManyToMany → User)
  • created_at, updated_at (Timestamps)
  • Methods: get_available_technician()

Category
  • name (String, unique)
  • description (Text)
  • assigned_group (FK → TechnicianGroup, optional)
  • created_at, updated_at (Timestamps)

Ticket
  • ticket_number (Auto-increment, unique display ID)
  • title, description (Strings/Text)
  • urgency (Low, Medium, High, Critical)
  • category (FK → Category)
  • location (String)
  • attachment (FileField, images only)
  • reporter (FK → User)
  • assigned_technician (FK → User, optional)
  • assigned_group (FK → TechnicianGroup, optional)
  • status (Open, In Progress, Resolved, Closed)
  • created_at, assigned_at, resolved_at, updated_at (Timestamps)
  • sla_response_time (Duration)
  • sla_resolution_time (Duration)
  • is_sla_breached (Boolean)
  • sla_breach_type (Response/Resolution)
  • Methods: assign_to_technician(), check_sla_breach(), is_overdue

TicketComment
  • ticket (FK → Ticket)
  • author (FK → User)
  • content (Text)
  • attachment (FileField, optional)
  • created_at, updated_at (Timestamps)

TicketHistory
  • ticket (FK → Ticket)
  • changed_by (FK → User)
  • field_name (String)
  • old_value, new_value (Text)
  • changed_at (Timestamp)
